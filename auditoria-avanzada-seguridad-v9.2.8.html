Resumen Ejecutivo para Dirección y Accionistas

Sugar Ludo v9.2.8 presenta una arquitectura multijugador sólida y un empaquetado multiplataforma impecable. La separación del portal web estático y la generación de binarios para Android y PC cumplen los más altos estándares de la industria gaming.

Sin embargo, en el ámbito Fintech y de Seguridad en la Nube, existe una vulnerabilidad estructural crítica: para permitir que el portal de administración funcione sin inyección de llaves de servicio (Service Account ADC), se abrieron las reglas de Firestore (firestore.rules) permitiendo que peticiones directas de cliente modifiquen saldos y bóvedas institucionales. Este hallazgo debe remediarse de forma prioritaria antes de abrir las transacciones con dinero fiat/USDT real.

2. Ciberseguridad & AppSec Defensivo

ZERO_TRUST_AUDIT

Hallazgo Crítico SEC-01: Exposición de Saldo en firestore.rules

En el archivo firestore.rules (líneas 25 a 27), se detecta la siguiente condición en la regla de actualización de usuarios:

firestore.rules (Regla Vulnerable Actual) CRITICAL VULNERABILITY
// Caso 3: Liquidaciones financieras y acreditaciones (Cajeros / Admin Hub / P2P) (request.resource.data.diff(resource.data).affectedKeys() .hasOnly(['coins', 'escrowLockedCoins', 'walletHistory', 'lastActiveAt', 'inbox', 'lastSettledDepositId']));
Impacto de Seguridad: Un usuario malicioso que obtenga la API Key pública de Firebase (presente en el bundle de JavaScript del frontend) puede ejecutar desde la consola de desarrollo de su navegador un script de Firestore SDK updateDoc(doc(db, 'users', 'su_uid'), { coins: 99999999 }). La regla lo autorizará porque los campos modificados caen dentro de la lista permitida, permitiendo inflación monetaria ilimitada.

Hallazgo SEC-02: Colecciones Financieras con Escritura Pública

Múltiples colecciones del sistema financiero cuentan con directivas allow read, write: if true;:

Colección Regla Actual Estado Riesgo Asociado
/system_treasury/{treasuryId} allow read, write: if true; Crítico Alteración arbitraria de las reservas globales y comisiones de la plataforma.
/cashier_profiles/{cashierId} allow read, write: if true; Crítico Modificación de saldo flotante asignado a cajeros y comisiones acumuladas.
/wallets/{userId} allow read, write: if true; Crítico Modificación directa de la billetera de cualquier jugador sin autenticación.
/audit_logs/{logId} allow read, write: if true; Crítico Inyección o borrado de trazas de auditoría para encubrir fraude.

Hallazgo SEC-03: Retiro Escrow iniciado desde el Cliente

En lib/wallet-service.ts (líneas 319-322), la función createWithdrawOrder() realiza una mutación directa de saldo en el cliente:

lib/wallet-service.ts (Línea 319) INCONSISTENCIA ARQUITECTURAL
// Mutación de saldo en el SDK cliente: await updateDoc(userRef, { coins: newCoins, escrowLockedCoins: newEscrow, walletHistory: history });

Esto contradice el principio rector estipulado en los comentarios de la misma biblioteca: "el cliente no muta directamente coins. Las mutaciones de saldo ocurren exclusivamente a través del backend autoritativo".

3. Economía Fintech, Bóveda Central & Red P2P

DOUBLE_ENTRY_TREASURY

Ecuación de Solvencia e Invariantes Financieros

El diseño económico de Sugar Ludo está fundamentado en el principio de doble entrada. Para garantizar solvencia matemática del 100%, debe verificarse continuamente:

Bóveda Central (USDT) = Σ Saldos Jugadores (Disponibles + Escrow) + Σ Flotantes Cajeros + Beneficio Neto Plataforma

Matemática de Comisiones y Puntos Básicos (BPS)

La deducción de comisiones implementada en el sistema aplica aritmética de punto fijo para evitar pérdidas por precisión IEEE-754:

Tipo de Retiro Tiempo Estimado Tasa BPS Comisión Plataforma Destino de la Comisión
Retiro Estándar Hasta 48 Horas 500 BPS 5.0% Bóveda Central (Patrimonio)
Retiro Prioritario VIP Hasta 12 Horas 1000 BPS 10.0% Bóveda Central (Patrimonio)
Incentivo al Cajero Inmediato (P2P) 200 BPS 2.0% Acreditado al Saldo del Cajero

Hallazgo FIN-01: Persistencia Efímera en Render (Disco Local JSON)

En sugar-ludo-admin-hub/lib/atomic-transactions.ts (líneas 8 a 35), el sistema implementa un almacén local en disco:

sugar-ludo-admin-hub/lib/atomic-transactions.ts WARNING: EPHEMERAL STORAGE
const DATA_DIR = path.join(process.cwd(), '.data') const DATA_FILE = path.join(DATA_DIR, 'cashier_orders.json') function loadDiskOrders(): CashierOrder[] { ... } function updateDiskOrderStatus(...) { ... }
Advertencia de Infraestructura Cloud: En plataformas PaaS como Render o Vercel, el sistema de archivos del contenedor es estrictamente efímero. Cualquier orden o estado guardado en .data/cashier_orders.json se destruye al desplegar una nueva versión, al escalar la instancia o al reiniciar el servicio. La persistencia DEBE residir 100% en Firestore.

SECURITY_HARDENING

Propuesta de Blindaje para firestore.rules (P0 Inmediato)

Sustituir de inmediato las reglas abiertas por el estándar RBAC protegido por Custom Claims y servidor autoritativo:

firestore.rules (Regla Blindada Propuesta) REMEDIATION READY
rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { function isAuthenticated() { return request.auth != null; } function isOwner(userId) { return isAuthenticated() && request.auth.uid == userId; } function isSuperAdmin() { return isAuthenticated() && request.auth.token.role == 'super_admin'; } function isCashier() { return isAuthenticated() && (request.auth.token.role == 'cashier' || isSuperAdmin()); } // 1. Usuarios: NINGÚN cliente puede modificar coins o roles match /users/{userId} { allow read: if true; allow create: if isOwner(userId) && (!('coins' in request.resource.data) || request.resource.data.coins <= 200); allow update: if isOwner(userId) && !request.resource.data.diff(resource.data).affectedKeys() .hasAny(['coins', 'escrowLockedCoins', 'role', 'isBanned', 'isFrozen']); allow delete: if false; } // 2. Billeteras, Tesorería y Auditoría: 100% blindadas contra SDKs cliente match /wallets/{userId} { allow read: if isOwner(userId) || isCashier(); allow write: if false; // Mutaciones exclusivas vía Firebase Admin SDK en Backend } match /system_treasury/{treasuryId} { allow read: if isSuperAdmin(); allow write: if false; // Solo Admin SDK } match /audit_logs/{logId} { allow read: if isSuperAdmin(); allow write: if false; // Inmutable desde el cliente } match /cashier_profiles/{cashierId} { allow read: if isCashier(); allow write: if isSuperAdmin(); } } }
